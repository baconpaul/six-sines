User wavetables for Six Sines

Replace the static SinTable read with a loaded multi-frame table, keeping every existing operator feature — PM, FM, RM, self-feedback, phase remap, resonant sweep — untouched. One FFT at load time buys the exact derivative, exact band-limiting, and the mip chain from a single piece of machinery.

Why this is cheaper than it looks

What the existing code already gives us

Four things in the current engine make this a smaller change than a wavetable oscillator usually is.

1. simdQuad is already a pointer

SinTable is a 16-byte object: a SIMD_M128 *simdQuad and a frToPhase scalar. All the table data is static. setWaveForm() does nothing but repoint simdQuad at a different slice of simdFullQuad. A single-frame wavetable is therefore almost free: point it at a heap-allocated frame and the inner loop never knows.

2. Hermite interpolation is linear in (q, dq), so morph is exact and cheap

at() is a dot product of the 4-vector (q[i], dq[i], q[i+1], dq[i+1]) against precomputed cubic coefficients. Because the dot product is linear in its first argument:

lerp(dot(q_lo, c), dot(q_hi, c))  ==  dot(lerp(q_lo, q_hi), c)

Crossfading two frames' packed vectors is bit-for-bit identical to crossfading two table reads, and costs one extra load plus a multiply-add instead of a second full at(). Frame morphing is one SIMD lerp.

3. Mode enums already latch at attack

OpSource::cacheEnums() freezes waveFormCachedAtAttack and friends in reset(). Latching which table at attack falls straight out of that, and it is what makes the lifetime problem tractable — a sounding voice can keep rendering the table it started on while the main thread swaps in a new one.

4. macroNames is the precedent for bulk patch state

Patch::setupAdditionalState() already hangs non-parameter, main-thread-only state off additionalToState / additionalFromState. Wavetable blobs are the same shape of thing, one order of magnitude larger.

The one thing nobody listed

Aliasing. A 2048-sample source cycle carries 1024 harmonics. At the engine's 240 kHz oversampled rate, harmonic 1024 of a 1 kHz note lands near 1 MHz. Your existing tables have fixed harmonic content and already alias mildly at the top of the keyboard; arbitrary user content will alias badly enough to be the first thing anyone hears. This is why the mip chain is in v1 rather than deferred.

Decision record

Settled questions

Table construction

FFT → harmonics → synthesize

Exact analytic derivative, exact band-limiting, arbitrary output resolution. Via pffft in libs/, not juce_dsp — keeps the loader JUCE-free and testable.

Anti-aliasing

Band-limited mip chain in v1

Level k keeps harmonics below H₀/2k at proportionally fewer points, so the whole chain costs ~2× level 0. Level picked per block from base frequency.

Memory budget

~8 MB per distinct table

512 harmonics, 8192-point base level, frame axis resampled to 64 frames. Sources sharing a table share the memory; worst case six distinct tables is ~48 MB.

Patch payload

Source samples, deflate + base64

Embed the source file verbatim. Load-from-file and load-from-patch become the same code path, and re-deriving harmonics at load keeps patches resolution-independent anyway. Warn only on explicit save, past 5 MB.

The hot loop

Template, never a runtime branch

MSVC on Windows x86 will not reliably hoist a ternary out of this loop. IsWT becomes a template parameter, 38 instantiations become 76, and the existing sine path compiles bit-identically to today.

Architecture

Load pipeline, runtime read, storage

The load pipeline

One path, used identically by the file chooser and by patch load:

bytes  // .wt / .wav / .sxwt, from disk or from the patch blob
  → parse            // → SourceFrames { cycleLength, nFrames, vector<float> }
  → forward FFT      // one per source frame, at cycleLength
  → frame resample   // linear along the frame axis, to ≤64 frames
  → per frame, per mip level k:
       harmonics 1..H_k, zero above
       inverse FFT              → value table   v[0..N_k]
       harmonics × j·2πn, IFFT  → slope table   dv/di[0..N_k]
  → interleave (v, dv) pairs, append wrap point
  → Wavetable { hash, name, nFrames, levels[] }

The derivative is a frequency-domain multiply, so it is exact — no finite differencing, no upsample-and-estimate. The same multiply-and-zero gives every mip level, and both fall out of machinery we need anyway. Note that this replaces the libsamplerate approach entirely on this path; libsamplerate stays where it is, downsampling the engine output.

Convention to get right

The static SinTable stores slope per table step using dxdPhase = 1/(nQuadrants*(nPoints-1)) — a shared-endpoint quirk that makes each quadrant span slightly more than a quarter cycle (~0.02% off). The wavetable path should use the exact 1/N convention with an explicit wrap point at index N, not replicate the quirk.

Runtime representation

// src/dsp/wavetable.h — immutable once built, shared across all voices
struct Wavetable
{
    struct Level
    {
        uint32_t nPoints;      // 8192 >> k
        uint32_t topHarmonic;  // 512 >> k
        uint32_t posShift, fracShift, posMask;
        // nFrames * (nPoints + 1) interleaved (v, dv) float pairs
        const float *data;
    };
    uint64_t   hash;                 // of the source bytes; the dedup key
    std::string name;
    uint16_t   nFrames;
    uint8_t    nLevels;
    Level      levels[maxMipLevels];
    std::vector<float> storage;      // owns everything above
};

Frames store interleaved (v, dv) pairs rather than the pre-packed 4-wide layout simdFullQuad uses. An unaligned 16-byte load at offset 2*i yields (v[i], dv[i], v[i+1], dv[i+1]) — exactly the Hermite 4-vector, for half the memory. Every other index is naturally aligned; the rest straddle by 8 bytes, which costs nothing inside a cache line.

The read path

Bit layout, mip level 0

13 bits position index — 8192 points/cycle
12 bits Hermite t → simdCubic
1 dropped

Phase stays the existing 26-bit accumulator. Level k has posShift = 13 + k, fracShift = 1 + k, posMask = (8192 >> k) - 1. The existing 4096-entry simdCubic coefficient table is reused unchanged — we just drop the bottom 1 + k bits of fractional precision feeding it, which at level 0 is 1 part in 33.5 million of a cycle.

The table read is a template dimension, not a branch

A runtime ternary in this loop is not acceptable — MSVC on Windows x86 does not reliably unswitch it, and this is the hottest loop in the synth. So IsWT becomes a real template parameter and the read resolves at compile time:

template <bool IsWT>
inline float readTable(uint32_t ph) const
{
    if constexpr (IsWT)
        return wtReader.at(ph);
    else
        return st.at(ph);
}

The eight st.at(ph) call sites in innerLoopImpl become readTable<IsWT>(ph), and innerLoopImpl gains IsWT alongside UsesFB. The same if constexpr guards the per-block mip level selection, so the non-wavetable instantiation never mentions wtReader at all and SinTable::at() keeps its constexpr shifts and masks. The existing sine path compiles to exactly the code it compiles to today — provably, not probably.

One call site does not change: stWindow.at(wph) in RESONANT_SWEEP. The sweep window is always a static SinTable waveform; only the operator's own waveform becomes a wavetable.

What it costs

The dispatch goes from 38 instantiations to 76: UsesFB × IsWT × {NONE, PHASE_REMAP×6, RESONANT_SWEEP×7, NOISE×5}, with one extra dispatch level at the top:

innerLoop()
  → usesWavetableCachedAtAttack ? Dispatch<UsesFB, true> : Dispatch<UsesFB, false>
      → switch extendedMode → switch shape → innerLoopImpl<UsesFB, IsWT, ET, S, R, NM>

Those instantiations land in the TUs that actually call renderBlock — voice.cpp and tests/perf_scenarios.cpp — not in every TU that merely includes synth.h. voice.cpp is therefore the one to watch on MSVC.

Mitigation held in reserve

If voice.cpp's compile time or object size becomes a problem, move innerLoopDispatch out of line into two translation units — op_source_render_sin.cpp and op_source_render_wt.cpp — with explicit instantiation, so the two halves compile in parallel instead of as one enormous TU. The per-block call overhead of an out-of-line dispatch is irrelevant next to eight samples of inner loop. Worth doing only if measured, since it costs the header-only simplicity of OpSource.

Morph

Morph is a live, modulatable, per-sample value, so it is deliberately not latched at attack. It follows the same shape as extendedModeM: patch value plus external mod plus env and LFO contributions, through a one-pole lag, then a linear walk across the block.

float m   = morph * (nFrames - 1);
uint32_t lo = (uint32_t)m;
uint32_t hi = std::min(lo + 1u, nFrames - 1u);
float    f  = m - lo;
// walked per sample: m += dMorph

Because time-domain frame interpolation and harmonic-domain frame interpolation are the same operation (the FFT is linear), block-rate frame-pair selection with per-sample weight matches what Serum and Surge do, and matches how we resampled the frame axis at load.

The store, dedup and lifetime

Bulk data reaching the audio thread is the genuinely new architectural piece — there is no precedent for it in the codebase. The design keeps the audio thread free of allocation, deallocation and locks:

  • WavetableStore lives beside patchMain, main-thread-mutated only. It holds std::array<std::shared_ptr<const Wavetable>, numOps> published — one publication cell per operator, indexed by operator, since an operator has exactly one table — plus a hash → shared_ptr dedup map. Loading a file whose bytes hash to a table already in the map reuses that allocation; that is the “two sources, one table” requirement, and it caps distinct tables at numOps by construction.
  • Publication is a new MainToAudioMsg::SET_WAVETABLE { opIndex } — the cell index is the operator index, so the message carries nothing but a small integer and stays POD. The main thread writes published[op], then pushes; the ring buffer's release/acquire pairing makes the write visible before the message is.
  • Back-to-back loads on one operator are the only ordering hazard: a second write to published[op] before the audio thread has consumed the first message would race the audio thread's copy. An outstanding[op] flag, cleared by an audioToMain ack, defers the second write until the first is consumed. At UI gesture rate this is invisible, and it avoids needing a ping-pong cell or a table pool.
  • The audio thread copies published[op] into monoValues.wavetableForOp[op] — a shared_ptr copy, one atomic increment, no allocation. OpSource::reset() copies it again into the voice at attack.
  • Nothing is ever destroyed on the audio thread, because a table displaced from published moves to a main-thread retiring list that keeps a reference alive. The main thread drops it only once use_count() == 1, polled from the existing idle / onMainThread path. So the store's steady-state size is numOps cells plus however many tables are briefly retiring.
Simpler fallback if this proves fussy

Bracket the swap in the existing STOP_AUDIO / START_AUDIO pair, which already calls allSoundsOff(). Then raw pointers suffice and lifetime is trivial. The cost is that loading a table cuts any held note — acceptable for a load gesture, mildly annoying while auditioning. The shared_ptr scheme above is barely more code and avoids it, so start there.

Patch serialization

Patch gains a main-thread-only WavetableSet wavetables — exactly the macroNames precedent — serialized through the existing additionalToState / additionalFromState hooks. Blobs are stored once and referenced, so a table shared by two sources appears once in the file too:

<wavetables>
  <table id="0" hash="9f3c…" name="Bells 3" srcFormat="serum-wav"
         cycleLength="2048" srcFrames="256" encoding="deflate-base64">
    eJyVk2t…
  </table>
</wavetables>
<sourceWavetables>
  <source idx="0" table="0"/>
  <source idx="3" table="0"/>
</sourceWavetables>

Compression uses sst-plugininfra::miniz, already vendored — flip SST_PLUGININFRA_PROVIDE_MINIZ on in libs/CMakeLists.txt and link the alias. No new submodule, and patch.cpp stays JUCE-free.

Why base64, and what it costs

The patch is an XML document, so the payload has to survive as text. CDATA cannot carry arbitrary bytes — NUL, the ]]> sequence and any invalid UTF-8 all break it — so base64 is forced, at 4/3 of the deflated size. The CLAP state stream underneath is perfectly binary-capable; it is the XML layer above it that isn't, and replacing that format is well outside this feature. Base85/Z85 would claw back 8 points of overhead for a non-standard encoding and a hand-rolled codec — not worth it.

The soft limit is 5 MB of encoded payload, which a single table never reaches — it fires only on a patch carrying several large verbatim sources. Past it, the editor offers to re-encode to the 64 frames actually used, which drops that Serum case to roughly 270 KB.

Where the warning lives

The size warning belongs only in the editor's explicit Save Patch path, never in Synth::stateSave. A DAW session save is not a user gesture: it must not dialog, must not block, and must not fail. It writes whatever the patch holds, at any size.

Robustness: a patch naming USER_TABLE with a missing or unparseable blob falls back to SIN and surfaces the failure in the UI rather than rendering silence. Factory patches embedding tables would grow the compiled binary, so that is an explicit later decision, not a side effect.

File formats

Three parsers, one output struct

Every parser produces the same SourceFrames { cycleLength, nFrames, vector<float> }, so the FFT pipeline downstream never branches on provenance.

Read these two files first

The local Surge checkout has both formats already solved, and the details below are taken from it rather than from memory: surge/src/common/dsp/Wavetable.h for the .wt header, and surge/src/common/WAVFileSupport.cpp for the .wav chunk chain — the latter is a decade of accumulated real-world edge cases and is worth reading in full before writing a line of the parser.

Sample data is table-major after the header. Surge's own ceiling is max_subtables = 512, a sane bound for us to reject beyond too. The trailing metadata XML carries a name, which is worth lifting for the UI label.

Serum-tagged .wav

Hand-rolled RIFF walk rather than a JUCE reader, for two reasons: it keeps the parser JUCE-free alongside the rest of the loader, and JUCE's WAV reader does not surface the non-standard chunks we need. Read fmt  for int16 / int24 / float32 and channel count; take channel 0 if stereo.

Frame size follows Surge's priority chain, which is more thorough than anything I would have invented:

  1. clm  — payload begins <!>dddd, e.g. <!>2048 10000000. Note Surge only recognises a literal 2048 here; we should parse the integer generally, which is a small improvement over the reference implementation.
  2. uhWT — Hive metadata, treated exactly like clm  (implies 2048).
  3. cue  — cue points delimit frames. Trust the chunk size over the cue count the chunk declares; they disagree in the wild.
  4. srge / srgo — Surge's own tag: int version then int frameSize.
  5. smpl — loop start/end give the length. An empty smpl block means 2048 (that quirk is RAPID's).
  6. Otherwise: power-of-two guess from the data length, preferring 2048, then prompt.

Six Sines .sxwt

tinyxml, matching the patch format's house style. Three frame kinds, in decreasing order of how much I recommend them:

  • kind="harmonics" — sparse sine/cosine coefficients. Tiny, hand-authorable, exactly band-limited, exact derivatives for free. This is the headline feature: a five-line XML file gives a mathematically perfect table. 
    <frame kind="harmonics">
  <h n="1" a="1.0"/>
  <h n="3" a="0.333"/>
  <h n="5" a="0.2" phase="0.25"/>
</frame>
  • kind="samples" — base64 float32 for one cycle; goes through the same FFT path as a .wt file.
  • kind="exact" — explicit (v, dv) pairs at a declared point count, bypassing the FFT entirely. This is the literal “function and derivative at Six Sines size” request, and it is the right tool for a genuinely non-band-limited analytic shape. Caveat worth stating plainly: it is the one representation coupled to a runtime resolution, so it must carry its point count and be resampled (or rejected) if the runtime size ever changes. The other two kinds are immune to that.
Still to check against real artifacts

The header layout and chunk chain above are confirmed against the Surge source. What is not confirmed is behaviour on files in the wild: int24 .wav, stereo sources, a clm  declaring something other than 2048, and frame counts above 256. Phase 5 should test against actual Surge and Serum wavetables, not only synthesized fixtures.

Interface

One menu section, one slider, one painter

  • showWaveformPopup() gains a trailing section: Load Wavetable…, a User Wavetables submenu scanning ~/Documents/Six Sines/Wavetables, and — when a table is loaded — the table's name and a Clear item. Picking a table sets waveForm = USER_TABLE in the same gesture, so there is no invalid intermediate state.
  • Morph appears in SourceSubPanel only when waveForm == USER_TABLE, using the existing setEnabledState() visibility pattern that already drives the phase-remap and noise controls. It comes with envToMorph and lfoToMorph knobs, matching how extendedModeM is presented. Hidden — not disabled — when nFrames == 1.
  • The waveform painter needs read access to the table, so the editor takes a WavetableStore & alongside its existing patchMainRef. Draw the interpolated current frame solid with the neighbouring frames faint behind it, so morph position is legible at a glance.
  • Clipboard — SupportsClipboard on a source node must carry the table reference, or copying op 1 to op 3 produces an operator in USER_TABLE mode with no table.
  • File chooser follows the existing juce::FileChooser + launchAsync pattern in six-sines-editor.cpp, filtering *.wt;*.wav;*.sxwt.
Behaviour to document in the manual

Changing which table an operator uses takes effect on the next note, because the table is latched at attack like every other mode enum in this engine. Morph is live. That split is deliberate and consistent, but it will read as a bug to anyone who has not been told.

Verification

Tests

Four new files in tests/, each added to the explicit source list in tests/CMakeLists.txt.

wavetable_build.cpp
Synthesize from a known harmonic set and assert the built table matches the closed form to better than −100 dB. Check the stored slope against a high-resolution finite difference. Forward-FFT each built mip level and assert energy above its topHarmonic sits below −120 dB. Golden values for a three-harmonic table at fixed phases, following the golden-source pattern already used for the output stages.
wavetable_io.cpp
Round-trip fixtures for all three formats. Ambiguous .wav frame-size inference. Truncated, zero-frame and absurdly-large inputs rejected without crashing or allocating wildly.
wavetable_stream.cpp
Patch save/load round trip. Two sources sharing one blob stay one allocation after reload — assert on pointer identity, not just equal samples. A stripped blob falls back to SIN. Version gating: a v12 patch with waveForm == 21 loads as audio in, not as a wavetable. Back-to-back loads on one operator serialize correctly through the outstanding ack. A displaced table leaves published, sits in retiring while a voice still holds it, and is reclaimed once the voice ends. Clipboard copy carries the table.
wavetable_dsp.cpp
Morph at 0, 0.5 and 1 equals analytic frame interpolation. Frame-lerp-in-packed-domain equals crossfade-of-two-reads bit for bit. Mip level switching is continuous across a boundary. A loaded table combined with PHASE_REMAP and with RESONANT_SWEEP renders finite output.

Plus a perf_scenarios.cpp addition — 8 voices, all six operators on a 64-frame table with morph under LFO modulation — and a confirmation that the existing plain-sine and no-self-feedback SIMD-baseline scenarios are untouched. With IsWT templated they should be identical rather than merely close; anything else means the dispatch leaked into the wrong instantiation.

Implementation order

Eight phases

Sequenced so each one is verifiable on its own, and so the perf question gets answered early — before there is much built on top of the answer.

  1. Dependencies and the build unit

    pffft as a submodule at libs/pffft, wrapped in a small static target; SST_PLUGININFRA_PROVIDE_MINIZ on. A wavetable-build translation unit with no JUCE dependency.

    Gate synthesize a table from a hand-written harmonic set in a test; derivative and band-limit assertions pass.

  2. Runtime read path, single frame

    Wavetable, WavetableReader, the IsWT template dimension through innerLoopDispatch and innerLoopImpl, USER_TABLE in the enum with its migration. One frame, one level, table supplied by a test.

    Gate six-sines-perf unchanged on the existing scenarios, plus a look at voice.cpp compile time and object size on MSVC — that is where the 76 instantiations land, and where the out-of-line TU split gets decided.

  3. Mip chain and level selection

    Chain construction, per-block level choice, hysteresis.

    Gate a bright table played chromatically to the top of the keyboard has no audible aliasing; band-limit tests green.

  4. Multi-frame and morph

    Frame axis, packed-domain lerp, wavetableMorph and its env/LFO depths, TargetID::MORPH.

    Gate morph under audio-rate LFO is click-free; packed-lerp equals two-read crossfade.

  5. File parsers

    .wt, Serum-tagged .wav, .sxwt, with fixtures. Work from surge/src/common/dsp/Wavetable.h and surge/src/common/WAVFileSupport.cpp in the local checkout rather than reinventing the chunk chain.

    Gate a real Surge table and a real Serum table both load and sound right — actual files, not only synthesized fixtures.

  6. Store, publication, serialization

    Dedup by hash, slot publication, SET_WAVETABLE, main-thread reclamation, patch blobs.

    Gate patch round trip; two sources one allocation; no allocation on the audio thread under ASAN with a sanitizer build.

  7. UI

    Menu section, file chooser, morph visibility, painter, clipboard, missing-table failure surface.

    Gate load, morph, save, reload, and copy an operator — all by hand in the standalone.

  8. Documentation and factory content

    doc/manual.md on the latch-at-attack behaviour and the .sxwt harmonic format. Decide separately whether any factory patches ship with embedded tables, given the binary-size cost.

    Gate your review.

Risks

What I would watch

  1. Build time and code size from 76 instantiations. This is the price of getting the table read out of the runtime and into the type system, and it is the right trade — a runtime ternary in this loop does not survive MSVC on Windows x86. The cost lands almost entirely in voice.cpp. Phase 2 measures it; the out-of-line two-TU split is the escape hatch.
  2. Mip level comes from base frequency, so heavy PM and FM still alias. The instantaneous phase increment under audio-rate modulation has nothing to do with dPhase. Every wavetable synth with FM has this problem; the engine's existing tables have a version of it too. Document it, do not chase it.
  3. Patch size. A Serum-sized table is ~2.4 MB of base64 in the DAW project file, forced by the XML container. Under the 5 MB threshold, so it lands silently — a real change in the feel of a Six Sines patch even when nothing warns.
  4. The AUDIO_IN renumbering. Agreed and accepted, but it is still the lowest-effort, highest-consequence item in the plan — four lines of migration plus a test, and it breaks user patches silently if forgotten.
  5. .wav files in the wild. The chunk chain is confirmed against Surge, but int24, stereo sources, non-2048 clm  declarations and frame counts above 256 are untested paths.
  6. pffft's licence is FFTPACK-derived and BSD-like, which fits the repo's MIT source / GPL3 combined-work position — worth confirming rather than assuming.
  7. Load time. A 256-frame source means ~1000 inverse FFTs, which should be well under 100 ms. If it is not, it moves to a juce::ThreadPool job, which drags UI state handling along with it. Measure in phase 5 before deciding.

Deliberately out of scope

A browsable wavetable library panel with preview; a shipped factory wavetable set; wavetable morph as a second dimension in the matrix; loading arbitrary samples as multi-cycle sources. All reasonable follow-ons, none of them needed for the feature to be complete and useful.
